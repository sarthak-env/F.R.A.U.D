# Let's Get Your Dataset!

Here's the deal, the dataset is too big to live on GitHub (the training file alone is 351.2 MB),
so you'll download it yourself. Don't worry, it takes about 5 minutes and I'll walk you through every step...

## Where to get the dataset from?

We're using the **Credit Card Transactions Fraud Detection Dataset** on Kaggle (by kartik2112):

Link: https://www.kaggle.com/datasets/kartik2112/fraud-detection

It's a free download, and you only need a free Kaggle account.

## Here is how to download it...

You have two options.

- Option 1 works on every computer and needs no setup.
- Option 2 uses the Kaggle command line, and the steps differ slightly for Windows, Mac and Linux.

Either way you need a free [Kaggle](https://www.kaggle.com) account.

### Option 1: Manual download (Windows, Mac, Linux)

1. Open https://www.kaggle.com/datasets/kartik2112/fraud-detection and log in.
2. Click **Download** and save the zip file.
3. Unzip it:
   - **Windows:** right-click the zip > **Extract All**
   - **Mac:** double-click the zip
   - **Linux:** `unzip archive.zip -d data/raw` (or use your file manager)
4. Make sure `fraudTrain.csv` and `fraudTest.csv` end up inside the `data/raw/` folder.

### Option 2: Kaggle command line

Run every command from the **root of the project** (the `fraud-guard` folder).

#### Step 1: Get your API token

1. On Kaggle, click your profile picture > **Settings**.
2. Find the **API** section and click **Create New Token**.
3. A file called `kaggle.json` is downloaded, usually to your Downloads folder.

> If Kaggle shows a different token format on screen, follow the instructions it gives you and
> skip to Step 3.

#### Step 2: Put `kaggle.json` in the right place

**Windows (PowerShell)**

```powershell
mkdir $HOME\.kaggle
move $HOME\Downloads\kaggle.json $HOME\.kaggle\
```

**Mac (Terminal)**

```bash
mkdir -p ~/.kaggle
mv ~/Downloads/kaggle.json ~/.kaggle/
chmod 600 ~/.kaggle/kaggle.json
```

**Linux (Terminal)**

```bash
mkdir -p ~/.kaggle
mv ~/Downloads/kaggle.json ~/.kaggle/
chmod 600 ~/.kaggle/kaggle.json
```

The `chmod 600` line makes the file readable only by you. The Kaggle tool warns you if you skip it.

#### Step 3: Install the Kaggle tool

**Windows**

```powershell
py -m pip install kaggle
```

**Mac / Linux**

```bash
pip3 install kaggle
```

#### Step 4: Download the dataset

This command is the same on Windows, Mac and Linux. The `--unzip` flag extracts the files for you.

```bash
kaggle datasets download -d kartik2112/fraud-detection -p data/raw --unzip
```

### Check it worked

First, make sure the files are in the right folder.

**Windows**

```powershell
dir data\raw
```

**Mac / Linux**

```bash
ls data/raw
```

You should see `fraudTrain.csv` and `fraudTest.csv`.

Now check that Python can read them:

```python
import pandas as pd

df = pd.read_csv("data/raw/fraudTrain.csv")
print(df.shape)               # about 1.3 million rows
print(df["is_fraud"].mean())  # under 1% fraud
```

If you see those numbers, you're all set! 

### Something went wrong?

| Problem | Fix |
|---------|-----|
| `kaggle: command not found` (Mac/Linux) or `'kaggle' is not recognized` (Windows) | Run it through Python instead: `python3 -m kaggle datasets download ...` on Mac/Linux, or `py -m kaggle datasets download ...` on Windows |
| `401 Unauthorized` | Your token is missing or in the wrong folder. Redo Step 2. |
| `403 Forbidden` | Usually a login or terms issue. Open the dataset page in your browser while logged in, accept any terms shown, then try again. |
| Files ended up in the wrong folder | Move `fraudTrain.csv` and `fraudTest.csv` into `data/raw/` |

Stuck on the CLI? Use Option 1. It gives you the same files.

## Wait a sec... Why are there two files?

| File | What it's for | Notes |
|------|---------------|-------|
| `fraudTrain.csv` | Teaching our model | About 1.3M transactions from an earlier period |
| `fraudTest.csv` | Testing our model | Transactions from a **later** period |

This matters! In real life, a bank trains on the past and has to catch fraud in the future. By using a
later period as our test set, we copy that real-world situation. We **don't** shuffle everything together
randomly.

## What's in each column?

| Column | What it means |
|--------|---------------|
| `trans_date_trans_time` | When the purchase happened |
| `cc_num` | The credit card number (we use it to group each card's history) |
| `merchant` | The shop name |
| `category` | Type of shop (grocery, gas, online shopping...) |
| `amt` | How much was spent |
| `first`, `last`, `gender` | Who owns the card |
| `street`, `city`, `state`, `zip` | The cardholder's address |
| `lat`, `long` | The cardholder's location |
| `city_pop` | Population of the cardholder's city |
| `job` | The cardholder's job |
| `dob` | Date of birth |
| `trans_num` | Unique transaction ID |
| `unix_time` | The time as a Unix timestamp |
| `merch_lat`, `merch_long` | The merchant's location |
| `is_fraud` | **Our target!** 1 = fraud, 0 = legit |

> ✅ Before you submit: run `print(df.columns)` on the real file and make sure this table matches.
> Fix anything that's different, then delete this note.

## The Three "golden" rules

1. **Never edit files in `raw/`.** Treat them like the original photo negatives. All cleaning goes
   into `processed/`, so you can always start over.
2. **Never commit data to Git.** The `.gitignore` already protects you, but double-check with
   `git status` before pushing.
3. **Don't feed identifiers to your model.** Names, card numbers, street addresses and transaction IDs
   are labels, not patterns. Your model would just memorize them.
